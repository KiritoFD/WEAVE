# L3 实现缺陷：fp16 autocast 让小的损失权重梯度精确下溢为零

**发现日期**：2026-11-10
**严重性**：高 —— 会让"小权重新损失项"完全无效，且**不报错、不警告、损失值照常增加**
**影响实验**：P2 的 G1a（λ_r=0.001）与 G1b（λ_r=0.003），两次全部作废

---

## 1. 现象

G1 的 ranking 损失确实被加进了总损失，日志可见：

```
RANKLOG step1: lam_r=0.003 L_rank=5.344614 term=0.016034 loss_after=0.264436
```

但训练完成后，权重与无 rank 的对照组**逐位相同**：

```
G0_ctrl          sha=a66a429aacc08470
G1a_rank_weak    sha=a66a429aacc08470   max|dW| = 0.000e+00
```

**损失值增加了，梯度却没有到达权重。**

---

## 2. 定位：λ 存在硬阈值

用完全相同的设置（microbatch 80 / accum 3 / 4 步 / seed 42），只改 λ_r，
与无 rank 的孪生运行比较权重：

| AMP | λ_r | `max\|dW\|` | 变化张量 |
|---|---:|---:|---:|
| **fp16** | 0.001 | **0.000e+00** | **0/113** |
| **fp16** | 0.003 | **0.000e+00** | **0/113** |
| **fp16** | 0.010 | **0.000e+00** | **0/113** |
| fp16 | 0.020 | 1.316e-03 | 113/113 |
| fp16 | 0.050 | 1.527e-03 | 113/113 |
| **bf16** | 0.001 | **1.465e-03** | **113/113** |
| **bf16** | 0.003 | **1.509e-03** | **113/113** |
| **bf16** | 0.010 | **1.523e-03** | **113/113** |

**fp16 下 λ ≤ 0.01 精确为零，λ ≥ 0.02 才生效。bf16 下没有这个悬崖。**

---

## 3. 机制

`torch.autocast(device_type="cuda", dtype=torch.float16)` 让中间激活与**反向传播的梯度**
以 fp16 表示。

fp16 的最小正规数约 **6.1e-5**，最小次正规数约 **6.0e-8**。

ranking 损失对 `z_cross` 的梯度只有 **4.04e-03**（实测）。乘以 λ_r：

| λ_r | λ_r · 4.04e-3 | 相对 fp16 最小正规数 |
|---:|---:|---|
| 0.001 | **4.0e-06** | 次正规区（精度极差） |
| 0.003 | 1.2e-05 | 次正规区 |
| 0.01 | 4.0e-05 | 次正规区边缘 |
| 0.02 | 8.1e-05 | **正规区** ✅ |
| 0.05 | 2.0e-04 | 正规区 ✅ |

**再经过网络各层连乘后，次正规区的那部分直接下溢为 0。**

bf16 的指数范围与 fp32 相同（最小正规数约 1.2e-38），所以 4e-6 完全不受影响。

---

## 4. 为什么这个缺陷特别危险

| 特征 | 说明 |
|---|---|
| **不报错** | 没有 NaN、没有警告、没有异常 |
| **损失值正常** | `loss_after` 确实增加了 0.016 |
| **梯度张量存在** | `autograd.grad` 返回 113 个非 None 张量，只是全为 0 |
| **权重看起来"训练过"** | 因为 V6 主损失正常工作，模型仍在收敛 |
| **结论会完全错误** | 会得出"ranking 损失对训练无效"的结论 |

**这是本项目第 8 个静默失败，也是第一个"损失值增加但梯度为零"的。**

---

## 5. 规避方法

| 做法 | 说明 |
|---|---|
| **新损失项用小权重时用 bf16 或 fp32** | bf16 指数范围同 fp32，无此问题 |
| **不要用 fp16 配 λ<0.02 的辅助损失** | 经验阈值，与损失自身梯度量级有关 |
| **必须有"权重是否真的变了"的守卫** | 见 §6 |
| 或用 GradScaler | 但本项目未使用，且 GradScaler 主要防 fp16 前向溢出，不解决小梯度下溢 |

---

## 6. 已加入的守卫

`run_v6_next_p2c.sh` 结尾：

```python
mx = max(|W_P2_G0_bf16 - W_P2_G1x_bf16|)
if mx == 0.0:
    print("FATAL: identical to the control -- the ranking term did not reach the weights")
    sys.exit(1)
```

**同一守卫必须用于 Q2 的 `--embed-style-lambda` 与 `--trust-lambda`。**

## 7. 对已完成实验的影响

| 实验 | 影响 |
|---|---|
| 24h 队列的 23 个臂 | **无影响** —— 它们只有一个损失（V6 主损失），没有小权重辅助项 |
| P1 的 R1 判别器 | **无影响** —— 单损失分类训练 |
| P1 的梯度探针（`gate.py`） | **无影响** —— 推理模式，无 AMP 训练 |
| **P2 的 G1a / G1b（第一次）** | **作废** —— 探针清零（见 `autograd_probe_zeroes_gradient.md`） |
| **P2 的 G1a / G1b（第二次）** | **作废** —— fp16 下溢（本文件） |
| **P2 的 G0** | 有效，但需用 bf16 重跑以与 G1 公平对照 |

---

## 8. 与第 7 个缺陷的关系

两次作废的原因不同但同类：

| # | 缺陷 | 静默方式 |
|---|---|---|
| 7 | 训练图上的 autograd 探针 | 梯度张量存在但全 0 |
| **8** | **fp16 小梯度下溢** | **损失值增加但梯度全 0** |

**共同教训：任何"新损失项是否真的生效"的结论，都必须用权重差分直接验证，
不能只看损失值或诊断打印。**
