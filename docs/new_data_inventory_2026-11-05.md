## 5. 与 D5 的兼容性

D5 现状（文档 + 磁盘核对）：5 类 `Early_Renaissance / Impressionism / Minimalism / Rococo / Ukiyo_e`，train 1000/类（`datasets/distinct5_512/train` + `train_512clean`），test 30/类；训练走 packed latent（`data/train/.latent_cache/packed/00..04_<style>.pt`），预处理是**直接 resize 到 512×512、JPEG q95**（[prepare_d5_512_clean.py](file:///m:/WEAVE/tools/prepare_d5_512_clean.py#L26-L30)）。

### 5.1 必须做的接入动作

1. **标签映射**：`Early Renaissance → Early_Renaissance`、`Ukiyo-e → Ukiyo_e`、`Minimalism/Rococo → 同名`；只保留这 5 个 `style` 值。
2. **重命名**：按 D5 约定 `Style__<artist-slug>_<title-slug>.jpg`（slug 规则同 WikiArt：小写、空格转 `-`）；否则 manifest/配对缓存无法与 D5 对齐。
3. **重采样**：`Image.open(...).convert("RGB").resize((512,512), BILINEAR)`，JPEG q95、非 progressive（与 D5 完全同参），再 VAE encode。
4. **清洗**：短边 <512 的（约 25%）按"升采样"或剔除二选一；>50 MP 图必须加像素上限或先降采样；`style` 为空的 986 行直接丢弃。
5. **去重**：CSV 内同一 `(artist, title)` 重复 218/843/106/112/143 条（按类），先按名称去重；再按与 D5 的像素近重复（上方 4.1）剔除。
6. **重建/追加 latent**：packed 缓存是"每类一个 .pt"，新增图无法零散追加，需重新打包并更新 `manifest.json`；`prototype_pairing_top8.pt` 也要重算（配对规则见 DATA.md §6.3）。
7. **split 卫生**：`test/test` 是 WikiArt 官方 hold-out（`in_train=False`）。若 D5 的 test 仍用于评测，新数据只能取 `train`，否则会改变评测口径。

### 5.2 不能直接用的部分

- 其余 **132 个非目标风格**（`Baroque`、`Realism`、`Cubism`…）与 986 条空风格行；
- 与 D5 重复的图（像素近重复 7%–68%，见 4.1）；
- 短边 <512 的 25%（若要严格质量口径）；<256 的 111 张；
- 极端大图（>50 MP）直接解码会触发内存/解压炸弹保护；
- 同名不同图的情形：33/1,000 张 CSV 尺寸与实际不符，说明**不能只信 CSV 元数据**；
- `test/test` 作为训练数据使用会破坏 WikiArt 官方 split 语义。

| 风格 | 新增 train | 新增 val | D5 + 新增 train |
|---|---:|---:|---:|
| Early_Renaissance | 400 | 74 | 1,400 |
| Impressionism | 6,759 | 1,230 | 7,759 |
| Minimalism | 74 | 10 | 1,074 |
| Rococo | 1,181 | 338 | 2,181 |
| Ukiyo_e | 338 | 141 | 1,338 |
| **合计** | **8,752** | **1,793** | **13,752** |

- 类规模比 Imp : Min = **7.2 : 1**（7,759 : 1,074）。
- **"每类至少新增 1,000"不可达**：只有 Rococo（1,181）与 Impressionism（6,759）能过线；ER 400、Ukiyo-e 338、Minimalism 74 都远远不够。若必须凑到 1,000/类，只能从 W5（`wikiart512_5style`，5 类约 3,600/类）补，本轮数据不支持。

**对训练与 `Δ_style` 的后果**

- 训练侧：7.2:1 的不平衡会让容量向 Impressionism 倾斜；无重采样/加权时，Minimalism（1,074）与 Ukiyo-e（1,338）只占训练集的约 8%/10%，其风格表征收益很小，别指望小类 Δ 有明显变化。
- 评估侧：D5 test 是 30/class 等量，**逐类 Δ 本身可比**；但 Δ 同时反映"风格可分性"与"训练样本量"，Impressionism 的 Δ 会被数据量放大，跨类的 Δ_style 排序不再等价于风格难度。
- 聚合口径：micro 平均会被 Imp 主导（新增占比 77%），**macro（5 类等权）才与等量 eval 对齐**；建议同时报逐类 Δ + 95% CI，并把 Impressionism 子采样到 400–1,000 做一次对照，避免把"数据多"读成"风格好学"。

### 6.5 预处理可行性（Windows 侧 512×512 q95）

实测基准（Windows Python 3.12 + Pillow 10.3：`draft()` 解码 → `convert("RGB")` → `resize(512,512, BILINEAR)` → 内存 JPEG q95 编码，不落盘）：**【实测】**

| 指标 | 单线程 | 12 线程 |
|---|---:|---:|
| 解码中位 | 12.5 ms | — |
| 编码中位（q95） | 1.3 ms | — |
| 单张合计 中位 / p90 | 14.2 ms / 34.1 ms | — |
| 吞吐 | ≈70 img/s | **198.9 img/s**（600 张实测） |

外推（**【估算】**，±30%）：

| 范围 | 张数 | 12 线程纯计算 | 含落盘/校验（估） | 产物大小（均值 117.3 KB/张，实测） |
|---|---:|---:|---:|---:|
| 全量净新增 | 12,256 | 62 s | 1.5–3 min | **≈1.41 GB** |

| 构图 | 横 6,574 / 竖 5,214 / 方 468 | 与 D5 同口径压成 512×512（会变形，保持一致比保真更重要） |

### 6.6 建议

**默认推荐：标准档 + 方案 (b) 全收，不做均衡。** 理由：

1. 均衡方案 (a) 只能加 370–790 张（对 5,000 张 D5 约 +7%–16%），投入产出比接近零。
2. 真实有效增量集中在 Impressionism（6,759 train），Rococo（1,181）可作第二验证类；其余三类只能算微量补充。
3. 不平衡用 class-balanced sampler 或 loss 加权就能缓解，成本远低于"等量封顶"丢掉 8,000 张。
4. 不用激进档：1,711 张 <512 的图升采样后纹理偏软，会与 D5 的 512 源图形成质量分层；除非专门做质量消融。
5. Minimalism 只 +74（+7.4%），报告里必须明确"该类无实质扩容"，不要据此更新 Minimalism 的 Δ 结论。
6. 合规边界：tier2 用了 WikiArt 官方 test split 作训练数据，之后不能再声称"在 WikiArt 官方 split 上评测"；若只用 D5 test 评估则无影响。想完全避免可退到保守档 8,100（train 6,676）。

## 7. 风险清单

1. **标签泄漏（同源/同画家跨 split）**：`artist_group=train_and_test` 占 86,150/103,250；5 个目标风格内 82%–87%（Minimalism 47%）。WikiArt 的 split 按作品而非按画家切分，同一画家（甚至同一作品的多个版本）会同时出现在 train/test。若用新数据扩充训练、又用官方 test 评测，会高估泛化。**【实测】**
2. **主题偏差（画家 ≠ 风格）**：`artist` 有 2,316 个，`style` 137 个，一人跨多风格普遍；Early_Renaissance 1,351 张仅来自 **25 位画家**，风格标签实际被少数画家主导；Minimalism 460 行/63 位画家，且 45.8% 与 D5 重复。按风格扩容很容易扩成"扩画家"。**【实测】**
3. **重复图**：CSV 内同名 `(artist,title)` 重复 1,386 条（Impressionism 833 条）；与 D5 的像素近重复按类 6.1%–53.9%（全量实测）；还有同作品不同扫描/版本（文件名与标题都不同）。只按文件名去重不够，必须像素比对。**【实测】**
4. **版权/许可缺失**：CSV 无 license、无 URL，只有 `source` 站点字段（wikiart 98,702 / wikipedia 4,381 / 空 167）。WikiArt 图像多为公有领域但仍受站点 ToS 约束；无逐图授权信息，不能声称"可直接商用"。**【实测】**
5. **解压/复制完整性**：当前已完成且与 CSV 精确对齐；但盘点初期确实观察到文件数增长与 1 个 0 字节文件——若任务在 15:47–15:55 之间启动会读到半成品。后续如再解压，必须先做"文件数=CSV 行数 + 0 字节=0 + 20s delta=0"三项检查。**【实测】**
6. **数据损坏/极端尺寸**：0 损坏（抽样 40），但存在 131.8 MP 与 669 MP 级图像，默认 PIL 会直接抛 `DecompressionBombError`；CSV 最大只记 107.3 MP，说明元数据不可全信。需 `MAX_IMAGE_PIXELS` 上限 + `draft()` 解码。**【实测】**
7. **元数据不一致**：3.3% 的图实际尺寸与 CSV 不符（1000 抽样 33 张）。任何用 `pixelsx/y` 做的筛选都要以实际头信息复核。**【实测】**
8. **风格标签噪声**：空 `style` 986 行；存在明显错标（如 `kiri nichol` 被标 `Neoplasticism` 且 `source`/`title` 为空）。低置信标签不宜进"保守/标准"口径。**【实测】**

## 8. Windows 原生 vs WSL `/mnt/i` 性能对照

同一批文件、同一段 Python 代码（`os.listdir` + `os.stat` + 读 4 KB 文件头），每次 1,000 张：

| 侧 | 批次 | 列目录+stat | 读 4KB 头 | 合计 | 倍数 |
|---|---:|---:|---:|---:|---:|
| Windows 原生 `I:\` | 前 1,000 | 161 ms | 582 ms | **744 ms** | 1.0× |
| Windows 原生（同批、热） | 1,000–2,000 | 72 ms | 255 ms | **327 ms** | 1.0× |
| WSL `/mnt/i`（冷） | 1,000–2,000 | 1,866 ms | 2,544 ms | **4,410 ms** | 13.5× |
| WSL `/mnt/i`（热，复测） | 1,000–2,000 | 1,493 ms | 2,154 ms | **3,646 ms** | 11.1× |

整文件顺序读（200 张，94.3 MB）：

| 侧 | 耗时 | 吞吐 |
|---|---:|---:|
| Windows 原生 | 0.14 s | **690.2 MB/s** |
| WSL `/mnt/i` | 1.25 s | **75.4 MB/s** |

**结论：WSL 走 `/mnt/i` 的元数据操作慢 11–13 倍，整文件读慢 9.2 倍。全能读 47.63 GB 需 Windows ~69 s / WSL ~632 s（10.5 min）。【实测吞吐 → 估算】** 若还要解码/缩放，差距只会更大（9p 下小文件随机读是主要瓶颈）。

### 建议方案（含耗时估算）

1. **在 Windows 侧做预处理**：解码 → `resize(512,512)` → JPEG q95（与 `prepare_d5_512_clean.py` 同参），输出到 `I:\Latent_Style\Data_512clean\<Style>\...`；多线程 12 路（该脚本现成支持）。
2. **只把 512px 结果拷进 WSL ext4**（例如 `~/data/new5_512`）：产物约 8–15 GB，按实测 75.4 MB/s 约 **2–3.5 min**；之后 WSL 侧读 ext4 是本地盘速度。
3. **在 WSL 里跑 VAE encode + packed 打包**（CUDA 只在 WSL）；103k 张 512px encode 的耗时受 GPU 与 batch 影响，**未实测**，需按 VAE 单图耗时外推，不要引用本报告中的读盘数字当编码耗时。
4. 备选（不推荐）：直接把 47.63 GB 原图拷进 ext4（约 10.5 min），再在 WSL 解码——省掉 Windows 预处理，但 WSL 内解码 + 大图内存风险更高（669 MP 图）。
