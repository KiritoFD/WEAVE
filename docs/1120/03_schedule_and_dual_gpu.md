## 三、双子 Agent 并发与 GPU 进程化协作规则

严格沿用 V25 验证通过的协作规范：

1. **禁止创建 Git worktree，禁止子 Agent 切换分支**：全部 Agent 共享当前仓库根目录与 `main` 分支。
2. **总控独占 Git 操作**：仅总控负责 `git add / commit` 与台账合并；子 Agent 严格按文件所有权编写独立新增文件。
3. **并发上限严格为 2（`Slot A` + `Slot B`）**：
   - **`Slot A`（科学测量与诊断分析）**：负责 `K0/K1/K2/K7` 遥测与报告（`docs/v26/4090/*.md`）、150 源聚类配对 Bootstrap CI、`SG-25` 与四类困难路线盲视分析、失败归因报告。
   - **`Slot B`（代码开发与单测）**：负责 `exp/v26/{gpu3060,gpu4090}/*.py` 与 `tests/v26/*.py` 编写、CPU 单元测试全绿验证、派发 `tmux` / `schtasks` 持久化脚本。
4. **GPU 任务进程化，Agent 任务短周期化**：
   - 4090 与 3060 各维持**唯一一条独占 GPU 串行队列**（4090 用 `tmux`，3060 用 `.bat + schtasks`）；
   - **子 Agent 确认远程队列进入运行态后即刻退出交付、释放并发名额**，禁止占用子 Agent 槽位等待 GPU。

## 四、失败不断链路由表（保障 72 GPU·h 完整闭环）

| 若该机制判负（FAIL / 无收益） | 立即切换动作（绝不中止整体队列） |
|---|---|
| `SR-CFG` 无收益 | 保留原 `C2nt` 单分支条件，3060 直接进入 `P2` 动态 SWD |
| `K0/K3` `Q32` 无收益 | **永久从最简主线删除 `Q32`**，仅保留 V21 历史消融记录 |
| 采样修复 `S1/S2` 无显著增量 | 保留最小修复 `S1` 与均匀风格采样，不扩大搜索 |
| 动态 `SWD` 无收益（`K2`/`P2`） | 回退原 VGG 均值损失，将 3060 `P3` 资源全力切入 `Ref-MultiScale` |
| `Ref-MultiScale`（`P3-A`/`K6`）无收益 | 删除新增 `T_ref32/64` 分支，转入轨迹一致性 `Rollout` |
| `Rollout`（`P3-B`/`K5`）无收益 | 保留 P2 最佳训练策略，P4 仅做零训练少步扫描 |
| 条件 `Reflow` 蒸馏坍缩 | 判负并保留原 RK2 最优步数（4–6 步），不强行掺入 MeanFlow/Shortcut |
| 全部新机制均未突破 | 以 V25 `C2nt` 作为兜底候选，完成全量对比、3060 正式测速与**诚实失败归因报告** |
