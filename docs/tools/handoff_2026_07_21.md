## 第一部分：远程 RTX 3060 实验启动（已完成）

### 1.1 背景与最终方案

远程 3060 服务器（`administrator@100.115.18.62:2222`，Windows，I 盘有 WEAVE 镜像）用于长训练任务。SSH 一断，子进程会被杀掉。最终可靠方案是 **schtasks**：

```
schtasks /Create /TN <TaskName> /TR <bat-full-path> /SC ONCE /ST 00:00 /RU "<user>" /IT /F
schtasks /Run /TN <TaskName>
```

封装工具：[tools/launch_remote_schtasks.py](file:///g:/GitHub/Latent_Style/WEAVE/tools/launch_remote_schtasks.py)
- `--bat <path> --task <name>`：创建并立即运行
- `--task <name> --check`：查询任务状态 + python 进程
- `--task <name> --kill`：停止 + 删除 + kill python

辅助工具：[tools/remote_cmd.py](file:///g:/GitHub/Latent_Style/WEAVE/tools/remote_cmd.py)
- 任意 PowerShell 命令远程执行（base64 EncodedCommand 绕引号地狱）

### 1.2 踩过的坑（按出现顺序）

| # | 症状 | 根因 | 修复 |
|---|---|---|---|
| 1 | `ssh -o LogLevel=ERROR` 在 PowerShell 里报 `LogLevel=ERROR 不是 OutputFormat 的合法值` | PowerShell 把 `-o` 解析为 `-OutputFormat` 的缩写 | 改用 Python `subprocess.run(["ssh.exe", ...])`，不要走 PowerShell |
| 2 | `subprocess` `text=True` 报 `UnicodeDecodeError 'utf-8' codec can't decode byte 0xce` | 远程 Windows 输出 GBK 中文 | 用 `capture_output=True`（返回 bytes），手动 `decode("gbk", errors="replace")` |
| 3 | 多行 PowerShell 脚本通过 SSH 传过去变成帮助文档 | SSH 把多行命令拆成多个参数 | 用 `base64.b64encode(script.encode("utf-16-le"))` 生成 EncodedCommand，远端 `powershell -EncodedCommand <b64>` |
| 4 | 远程 PowerShell 返回 CLIXML 而非纯文本 | 默认输出格式 | 加 `-OutputFormat Text` |
| 5 | `scp` 报 `dest open ... No such file or directory` | 远程父目录不存在 | SCP 前先 SSH `New-Item -ItemType Directory -Force` |
| 6 | `Start-Process -FilePath 'cmd.exe' -ArgumentList '/c', $bat -WindowStyle Hidden` 启动的任务在 SSH 断开 5 秒后被杀 | Start-Process 启动的进程仍绑定到 SSH session | 改用 schtasks（独立 session） |
| 7 | schtasks `/Create` 报 `错误: 系统找不到指定的文件`，即使 .bat 存在 | `/TR` 用了 `cmd /c <bat>` 包裹；schtasks 解析失败 | `/TR` 直接用 .bat 全路径（参考 A1Eval 任务 XML） |
| 8 | LF-only 的 .bat 在某些 Windows 路径下行为异常 | 行尾问题 | 创建任务前 `Get-Content -Raw` → 替换 `\r\n` → `\n` → `\n` → `\r\n` → 重写 |
| 9 | `.gitignore` 第 82 行 `WEAVE/exp/**` 屏蔽所有 exp 子目录 | 历史规则 | 用 `git add -f` 强制添加 summary.json/csv/png |
| 10 | `git commit -m "$(cat <<'EOF'...)"` 在 PowerShell 报 `Missing file specification after redirection operator` | PowerShell 不支持 bash heredoc | 改用多个 `-m` 参数，每个 `-m` 一段 |

### 1.3 速度问题（用户问的"为什么这么慢"）

A3 α sweep 在远程跑了约 **57 分钟**（α=0.1/0.2/0.4/0.5 各 15 epochs + final eval）。慢的原因：

1. **训练阶段**（每 α ~10 分钟，共 ~40 分钟）
   - 15 epochs × 52 batch/epoch × batch_size=96 = 74880 samples
   - RTX 3060 12GB + bf16 AMP，单 epoch ~40s
   - 这是固定开销，无法压缩（除非减 epochs，但那样不可比）

2. **评估阶段**（每 α ~4 分钟，共 ~16 分钟）
   - final_only 路径：`run_evaluation.py` 推理 750 张 + `eval_baseline_per_sample.py` 算 CLIP-S/LPIPS/DINO-S/DINO-C
   - LPIPS + DINOv2-small 编码 750 gen + 150 src + 150 refs 是主要耗时
   - 不可压缩

3. **轮询开销**（次要）
   - SSH 每次重新握手 ~1-2s
   - 没有启用 SSH ControlMaster（可在 `~/.ssh/config` 加 `ControlMaster auto` + `ControlPath` 复用连接）

4. **第一次跑被杀掉的浪费**
   - 用 Start-Process 启动的 A3AlphaSweep 在 α=0.1 Epoch 1/15 0% 就被杀
   - 没有生成 err.log（taskkill 不写 stderr）
   - 浪费约 5 分钟定位

**结论**：57 分钟是合理的，无法显著加速。真正的浪费是前期试错（Start-Process vs schtask）。

## 第二部分：DINO-S `max → avg` 改造（未完成，交接）

### 2.1 用户诉求

> "目前的 dino-s，居然使用的是 max，我觉得受极端值影响太大了，希望改成 avg，用 weave/results 下面的数据，能做出新的主表数据吗"

### 2.2 现状探明

#### 当前 DINO-S 定义（`max`）

两处实现，都用了 `.max()`：

1. **[utils/compute_dino_metrics.py:165](file:///g:/GitHub/Latent_Style/WEAVE/utils/compute_dino_metrics.py#L165)**
   ```python
   style_scores = reference_cls @ generated_cls[index]
   dino_style.append(float(style_scores.max().item()))
   ```
   这是**论文主表数据源**（生成 `state/dino/*.json` → 汇编到 `aaai2027_v4/fig_data/dino_main.json` → 被 `make_radar*.py` / `plot_page1_summary.py` 读取）

2. **[tools/eval_baseline_per_sample.py:427](file:///g:/GitHub/Latent_Style/WEAVE/tools/eval_baseline_per_sample.py#L427)**
   ```python
   ref_cls = style_reference_cls[p["tgt_style"]]
   scores = ref_cls @ gen_cls[j]
   dino_s_vals.append(float(scores.max().item()))
   ```
   这是 sweep 脚本用的（A3/B 系列实验的 per-sample 协议）

两处都注释为 "max cosine CLS(gen), CLS(target-style reference)"。

#### 数据源现状（关键障碍）

**问题：`results/` 下没有 per-sample DINO CSV，只有聚合 JSON**

- [results/D5-512/weave_yfix_eval/](file:///g:/GitHub/Latent_Style/WEAVE/results/D5-512/weave_yfix_eval)：有 `metrics.csv`（含 dino_style 列）+ `summary.json`
- [results/D5-512/weave_eval_baseline/](file:///g:/GitHub/Latent_Style/WEAVE/results/D5-512/weave_eval_baseline)：有 `metrics.csv` + `summary.json`
- **但 baselines 目录（cut/samam/samst/sdturbo/seedream/stylealigned/styleid/styleshot/wct/zstar/adain/aespa/stytr2）下没有 metrics.csv**，只有图片
- baseline 的 DINO-S 聚合值存在 [state/dino/D5-512__<method>.json](file:///g:/GitHub/Latent_Style/WEAVE/state/dino)（750 张图的均值，但没保留 per-sample）
- 主表数据从 [aaai2027_v4/fig_data/dino_main.json](file:///g:/GitHub/Latent_Style/WEAVE/aaai2027_v4/fig_data/dino_main.json) 读取（同样是聚合值）

**这意味着**：不能"直接从 results/ 下重算 avg"，因为 baselines 没有 per-sample 余弦相似度，只有 per-sample 的 `max` 值。要改成 avg 必须重跑 DINO 评估（重新编码所有 gen + refs，算平均而非最大）。

**总时间**：脚本写好后，远程跑约 1-1.5 小时；论文手工更新约 30 分钟。
