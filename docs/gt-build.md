# WEAVE 伪GT实验 V2：单卡RTX 3060，24小时

修正两点：硬件是单卡RTX 3060 12GB；所有伪GT都应离线生成并缓存为latent，训练时直接读取配对latent。

这会大幅减少VAE调用、磁盘占用和训练阶段的不确定性。

本轮继续保留原计划的5种构造方法、28组patch配置，但只让质量筛选后的2组进入完整训练。主要实验预算投入伪GT质量研究，而不是28次模型训练。

## 一、总体技术路线

```
现有18K真实画作（只读）
          │
          ├── VAE编码 → 原图latent缓存
          │
          └── DINO内容特征 → 跨风格内容匹配
                                │
                                ▼
                       Patch位置及对应关系
                                │
               ┌────────────────┴──────────────┐
               ▼                               ▼
         正向伪GT构造                      反向污染构造
         A/B/C/D                               E
               │                               │
         x真实 → y伪                        x伪 → y真实
               └────────────────┬──────────────┘
                                ▼
                      离线缓存配对latent
                                │
                     质量评测 → 选2组
                                │
                         Paired FM训练
                                │
                        600跨风格评估
```

### 关键工程决策：全部离线缓存latent

对不同构造方法分别处理：

| 方法              | 构造位置        | 缓存内容         | 训练时  |
| --------------- | ----------- | ------------ | ---- |
| A/B：RGB Patch替换 | RGB拼贴后VAE编码 | 改变后的目标latent | 直接读取 |
| C：HF Patch替换    | Latent空间    | 改变后的目标latent | 直接读取 |
| D：局部统计替换        | Latent空间    | 改变后的目标latent | 直接读取 |
| E：反向Patch污染     | RGB拼贴后VAE编码 | 改变后的输入latent | 直接读取 |

RGB先拼贴再VAE编码，与直接拼接latent不是等价操作。 为保证实验能区分两种方法，A/B/E仍先完成RGB变换，但只保存最终latent，不保存完整伪图像。

原图latent也只编码一次。训练阶段不加载VAE、不进行patch匹配、不执行数据构造、不需要任何外部特征模型。

## 二、缓存量与显存

512px图像使用4×64×64 latent，FP16存储。

单张latent：

\\[ 4\times64\times64\times2=32\ \mathrm{KiB} \\]

| 缓存                           | 数量      | 容量        |
| ---------------------------- | ------- | --------- |
| 原始18K latent                 | 18,000  | 0.55 GiB  |
| 28组质量测试，每组300个               | 8,400   | 0.26 GiB  |
| 一个入选方案，每张训练图2个版本             | 约35,000 | 1.07 GiB  |
| 两个入选方案                       | 约70,000 | 2.14 GiB  |
| DINOv2-S patch特征（16×16，384维） | 18,000  | 约3.30 GiB |

加上检索索引、元数据、训练结果，预计新增磁盘占用约7–10 GiB，不含已有模型和原始数据。

为避免12GB显存不足，DINO、CSD和VAE在各自阶段分开运行。训练只加载WEAVE，数据从CPU端的连续latent缓存分批送入GPU。

如果已有latent缓存符合本轮VAE权重、缩放系数及posterior mean协议，直接复用；否则在实验目录新建缓存，绝不覆盖旧文件。

## 三、28组伪GT构造实验

统一在512px下定义patch尺寸。

### 3.1 九种Patch配置

| ID | Patch大小            | 数量 | 覆盖率   |
| -- | ------------------ | -- | ----- |
| P1 | 64×64              | 8  | 12.5% |
| P2 | 64×64              | 16 | 25%   |
| P3 | 64×64              | 32 | 50%   |
| P4 | 128×128            | 2  | 12.5% |
| P5 | 128×128            | 4  | 25%   |
| P6 | 128×128            | 8  | 50%   |
| P7 | 256×256            | 1  | 25%   |
| P8 | 256×256            | 2  | 50%   |
| P9 | 128×128×1＋64×64×12 | 13 | 25%   |

同一配置内的patch不重叠。

### 3.2 五类构造方案

| 方向            | 实验配置                      | 数量 | 构造方式                      |
| ------------- | ------------------------- | -- | ------------------------- |
| A：RGB硬替换      | P1–P9                     | 9  | 直接复制内容匹配的目标风格patch        |
| B：RGB软融合      | P2、P5、P7、P9               | 4  | 与A使用相同patch，边缘Feather融合   |
| C：Latent HF替换 | P2、P5、P7、P9               | 4  | 替换LH、HL，保留LL、HH           |
| D：局部统计迁移      | P2、P5、P7、P9               | 4  | 逐patch匹配LL/LH/HL的mean/std |
| E：反向污染        | P2、P3、P5、P6、P7、P9、P5-Hard | 7  | 向真实目标画作注入异风格patch，再恢复真实画作 |
| 合计            |                           | 28 |                           |

另外补4个对照：无注入、随机内容匹配、同风格patch注入，以及仓库已有的`destyle_latent`。

A/B与E需要真正的RGB合成后再编码；C/D可以直接操作已有latent。

对于C/D，应特别检查构造差异中有多少能量落在WEAVE实际预测的LL/LH/HL里。否则伪GT看上去变化很大，但训练网络没有对应输出头，实验就没有意义。

### 3.3 特别重视反向方案E

正向构造：

\\[ z_x\longrightarrow z\_{\rm pseudoGT} \\]

反向构造：

\\[ z\_{\rm corrupted}\longrightarrow z\_{\rm realGT} \\]

E有一个明显优势：GT是真实艺术作品。

但有风险：25%异风格patch污染的图像仍有75%的目标风格，模型可能只学会局部修补。

因此E必须重点比较25%和50%覆盖率，并额外加入P5-Hard，检查收益是不是来自识别拼贴接缝。

本轮不增加任何重建损失或对抗损失，先纯粹比较训练数据构造。

## 四、内容匹配如何适配3060

不能对18K作品做高分辨率全量两两patch匹配。那会浪费大量时间。

采用三级漏斗。

第一级：全18K整图检索。

复用或提取DINOv2-S特征，在其他四类风格中分别检索Top-8内容相似作品。

通过分块矩阵乘法完成相似度计算，不需要大型检索服务。

第二级：只对候选做局部匹配。

初期在500张逻辑验证作品中抽样300张，五种风格各60张。

同一批源图、目标风格、内容匹配结果和patch位置，供28组构造方案共用。

局部匹配使用DINO patch tokens、双向最近邻与空间一致性检查。优先选择内容结构对应良好的区域。

第三级：入选方案才扩展到完整训练集。

假设一个候选匹配失败，允许换Top-8中的其他作品；全部不满足时记录失败，不强制生成。

只对通过筛选的两个构造方案，为训练样本建立完整对应关系。

### 数据划分

现有18K目录只读，通过manifest逻辑划分：

- 17,500张：伪GT训练池。
- 500张：伪GT质量验证池。
- 原有150张test：最终真实跨风格评测。

500张验证池不参与训练和检索供体，防止实验方案选择与训练数据泄漏。

所有处理只写入`runs/pseudo_gt_24h/`。

## 五、先评估数据质量，而不是立即训练

28组每组300个样本，总计8400个候选。

全部只保存改变后的latent与manifest。 需要人工检查时，从latent解码少量样例并制作contact sheet。

| 评价维度   | 指标                | 目的            |
| ------ | ----------------- | ------------- |
| 目标风格方向 | CSD ΔT、ΔS         | 判断是否真的朝目标风格变化 |
| 内容保持   | DINO-C、LPIPS      | 排除拼贴改变语义内容    |
| 匹配质量   | Mutual NN比例、结构一致性 | 判断内容检索的价值     |
| 接缝异常   | Patch边界梯度异常       | 排除模型学习拼贴痕迹    |
| 可学习监督  | LL/LH/HL目标差异能量比例  | 检查当前网络是否能学习   |
| 可用样本比例 | 通过筛选数量/请求数量       | 判断方案能否规模化     |

对于反向E，CSD应当验证两个方向：伪输入是否增强了供体源风格，以及真实GT是否比伪输入更接近目标风格。

筛选不能只按CSD分数排名。应先淘汰明显改变语义或产生严重接缝的方案，再比较风格变化和覆盖率。

最终选择两个候选：一个来自A–D，一个来自E。

这样最重要的正向伪GT与反向真实GT可以在相同训练预算下直接比较。

## 六、只对入选方案建立完整训练缓存

每个方案从17,500张真实画作出发，生成每张2个随机版本：

\\[ 17,500\times2=35,000\text{组配对} \\]

正向A–D，每张源图选择非本源目标风格；反向E，每张真实目标图选择异风格供体。五类目标及20种跨风格方向尽量均衡。

每组配对的manifest记录：

`source_id`、`donor_id`、`target_style_id`、`patch_spec`、`match_score`、`seed`、`changed_latent_offset`。

两边未修改的真实图像latent只引用公共缓存，不重复存储。

生成完成后：

- 伪GT构造与模型训练完全解耦。
- 同一伪GT可被多个模型重复使用。
- 不同seed可使用相同训练配对，隔离模型随机性。
- 不需要把RGB拼贴图存储成PNG。

这也是为什么我认为本轮所有入选方案都应该离线缓存，而不是仅缓存部分方案。

## 七、固定训练方案

这一轮只研究伪GT质量，不更改网络结构。

| 配置              | 设置                    |
| --------------- | --------------------- |
| GPU             | RTX 3060 12GB         |
| 模型              | 现有约1M WEAVE           |
| 训练方式            | 从头训练，paired-FM        |
| 有效batch         | 256                   |
| Microbatch      | 16或32，按显存选择           |
| LR              | 2×10⁻⁴                |
| 训练步数            | 2000                  |
| Checkpoint      | 250、500、1000、2000     |
| 频带权重            | LL 0.3，LH/HL 1.0，HH关闭 |
| 推理              | 8步ODE，关闭AdaIN         |
| 额外损失            | 无                     |
| 训练时VAE/CSD/DINO | 全部不加载                 |

需确保训练真正使用缓存的原始配对latent。

仓库`flow.py`默认可能对训练终点再次执行SAT和LL风格变换。本轮必须绕过这些操作，否则实验比较的就不是构造好的伪GT。

训练三组：

- 原始FM基线，相同步数。
- 入选正向伪GT方案。
- 入选反向真实GT方案。

训练时对每组独立使用相同优化器设置、更新次数、初始化seed和有效batch。

新模型最终在真实的600跨风格任务上评估，不能把伪数据训练误差当作成功依据。

## 八、24小时预算

按单卡3060重新安排，不依赖4090性能估算。

| 时间预算   | 工作                              | 产物            |
| ------ | ------------------------------- | ------------- |
| 0–1h   | 环境检查、只读manifest、100张样本速度基准      | 实测GPU吞吐与缓存速度  |
| 1–4h   | 全18K特征与原图latent缓存、Top-8整图检索     | 内容检索索引        |
| 4–7h   | 验证集局部匹配、patch位置和置信度             | 共享匹配记录        |
| 7–11h  | 构造28×300候选、缓存latent、CSD/内容/接缝测量 | 28组质量表        |
| 11–12h | 筛选正向和反向各1组                      | 两个入选方案        |
| 12–16h | 各生成约35K训练配对并缓存                  | 约70K伪数据latent |
| 16–20h | 三组2000步训练与中途检查                  | 三套训练曲线        |
| 20–23h | 真实600跨风格＋150同风格评估               | 新旧模型对比        |
| 23–24h | 失败案例、逐风格分析、最终报告                 | 决定哪些伪GT有效     |

这是24小时计算资源分配上限，不是对各阶段实际耗时的保证。

在第1小时先实测VAE编码、CSD评估和WEAVE单步训练吞吐。如果后续阶段超过预算，优先减少入选方案的缓存版本数，而不是取消28组构造质量对照。

如果伪GT质量筛选显示所有方案都有严重内容破坏，则不继续消耗预算训练。

## 九、最终决策标准

主要评估仍为600跨风格CSD ΔT，附带ΔS、ΔM及DINO-C/LPIPS。

现有完整WEAVE的CSD ΔT约为+0.0203。新实验必须在同一固定评测latent协议下复算基线，不能直接把不同随机编码口径的结果横比。

最关注以下结果：

| 结果                       | 对下一步的意义                 |
| ------------------------ | ----------------------- |
| 正向伪GT有效，反向无效             | 优先研究内容锚定的局部风格化          |
| 反向真实GT明显更好               | 继续研究更强的异风格污染与恢复         |
| 小patch优于大patch           | 局部纹理迁移比区域内容交换更可靠        |
| 大patch改善风格但破坏内容          | 需要更强的语义对齐，而不是增加替换比例     |
| 两者训练集表现很好，真实600不改善       | 主要瓶颈是伪数据与真实跨风格输入之间的分布差距 |
| Rococo、Ukiyo-e的ΔT转正且内容稳定 | 说明伪GT方向确实有突破价值          |

## 最终执行原则

28组只做数据质量实验，2组进入完整训练，1组原FM对照；单卡3060、24小时、18K数据集完全只读。

与上一版相比，最大的调整是：

所有变换全部离线完成，训练时只加载FP16 latent配对。原图latent只存一次，伪GT只存变化后的latent，不再保存大量RGB图片，也不在训练步骤里运行VAE或patch构造。

这样24小时主要用于回答“什么伪GT有效”，而不是浪费在重复编码和复杂数据加载上。
