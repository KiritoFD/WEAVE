# 更正：Minimalism 吸引子从未消失（0.000 是类型 bug）

**日期**：2026-11-10
**严重性**：高 —— 把一个**主要弱点**误报成**主要优势**
**影响范围**：P2、Q1、Q2、Q3 四份结果文档 + 最终报告

---

## 1. 错误

我在 P2 / Q2 / Q3 / 最终报告中反复声称：

> "非目标 Minimalism 误判率 **0.000**，对照 ScoreDiff 约 0.32 —— **本路线完全没有继承单类吸引子**"
> "六个臂在两个层级上都是 0.000 —— 完全没有单类吸引子"

**这个结论是错的。**

---

## 2. 根因

`tools/v6_24h/eval_tiers.py:202` 存的是**整数索引**：

```python
"pred_class": int(sc.argmax()),
```

而我的 `q0_verify.py::offdiag_min` 拿它和**字符串**比较：

```python
hits = [r for r in non_min if r.get("pred_class") == "Minimalism"]   # 永远 False
```

**`int == str` 恒为 False → 计数恒为 0 → 报告 0.000。**

同一份 `eval.json` 里的混淆矩阵（由同一个整数索引构建）是**正确的**，
所以两者互相矛盾，而我只看了一个。

| 说法 | 状态 |

2. **任何从 rows 计算的派生指标，都必须与同一文件里的聚合量交叉核对**
