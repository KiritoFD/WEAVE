# V35 CLEAVE-One：开放域单参考图风格迁移实验阶段报告

> **状态快照（2026-11-26）**：已完成 **Stage P0**（WikiArt 29+5 画派严格去重与 `StyleEncoderC` 自监督探针）、**O0 / O1 / O2 / O3** 四个训练臂（`O3` 在 12GB RTX 3060 上稳定完成 `1,400` 步微调，峰值显存 **`5.18 GB`**）、**9 组完整 `test750` + 开放域 OOD 评测**，以及 RTX 3060 端到端吞吐分段剖析。用户于 20:29 指令中止长队列后，`O3` 高 `tau0` 点（`0.50/0.65/0.80`）、`4-step wc=1.0` 极速质量验证与 `O4`（44M）扩容消融暂未执行；本文档基于已落盘的 `*_full_report.json` 与实测脚本如实归档，不包含未运行推测。

---

## 1. 核心进展与一句结论

**在不依赖任何推理期画派标签（zero `sid`）、训练集检索（zero kNN）及测试模型蒸馏（Zero-DINO/CSD/CLIP/LPIPS 训练隔离）的前提下，V35 `O3`（`StyleEncoderC` + 可微 `S10` + 冻结 `VGG-16` Reference Swap）已在严格未见画派（`Movement-OOD = 92.50%–93.33%`）与同画派实例交换（`Instance-Swap = 83.33%–85.00%`）上显著跨越目标阈值，并把 `test750 Cross600 CSD Top-1` 从 `O0` 的 `14.50%` 连续推升至 `48.50%`（错标签因果差最高 `+36.00pp`）。**

同时，实验也锁定了当前 `O3`（`22.3M` P-Core，噪声线性初始化）的真实短板：`DINO-C` 与 `CSD Top-1` 尚未同时迈入 `(>=0.60, >=60%)` 区间（`O3_t35` 为 `0.4361 / 40.50%`，`O3_t00` 为 `0.3221 / 48.50%`）；且 `batch=1` 冷启动端到端延迟在 `4-step wc=1.0` 下为 `237.82 ms/img`（`4.20 img/s`），在 `batch=4/8` 下突破 `>= 5 img/s` 达 **`5.24–5.49 img/s`**。

## 2. 合规性与数据隔离核查

- **零裁判泄漏（Zero-DINO Training）**：训练入口 [train_pcore_oneshot.py](../../exp/v35_cleave_one/train_pcore_oneshot.py) 与损失函数 [losses.py](../../exp/v35_cleave_one/losses.py) 仅使用 `PseudoHuber_0.05` 速度场损失、无监督对比+属性重建损失（[probe_encoder.py](../../exp/v35_cleave_one/probe_encoder.py)）以及冻结 `VGG-16` 风格/灰度内容损失，完全隔离 `DINOv2`、`CSD`、`CLIP`、`LPIPS`。
- **编码器规模与条件机制**：`StyleEncoderC` 实测总参数 **`2,384,865`**（`<= 3M` 上限），结合 [style_features.py](../../exp/v35_cleave_one/style_features.py) 提取的 `1,561-D` 显式多尺度统计向量与无序 ConvNeXt S1/S2/S3 Patch 交叉注意力（无位置编码），经 [models.py](../../exp/v35_cleave_one/models.py) 的每层独立 `AdaGN` 注入 `OneShotPCoreNet`（继承 `V32` 骨干除离散标签头外的 115 个权重键）。
- **解码器契约**：所有训练前向反传与评测出图严格经 [src/utils](../../src/utils/__init__.py) 的 `load_s10_decoder` / `decode_s10(..., enable_grad=True/False)`，未使用原版 `SD-VAE` 解码器。
- **严格 OOD 数据隔离**（见 [curation_summary.json](../../runs/v35_cleave_one/curation_summary.json) 与 [prepare_data.py](../../exp/v35_cleave_one/prepare_data.py)）：
  - `Seen-Train`：`19,997` 张预计算样本（覆盖 `29` 个可见画派、`969` 位多作品艺术家）。
  - `Artist-OOD`：`500` 张可见画派但完全未见艺术家作品（严格按艺术家、标准化画作 ID `canonical_pid` 与 `16×16` 缩略图去重）。
  - `Unseen-Movement-OOD`：`500` 张来自 **5 个训练完全不可见画派**的作品（`Pointillism`、`Cubism`、`Pop Art`、`Art Nouveau (Modern)`、`Fauvism`），且不参与任何均值/方差归一化或 Stiefel 基拟合。

## 5. 关键工程与机理发现

1. **可微 `S10 + VGG-16 Reference Swap` 是同画派细粒度与强风格转移的最大引擎**：
   在完全相同的 `tau0=0.30, wj=3.2, wc=1.6` 采样设定下，`O3_t30` 相比无 Swap 的 `O2_t30`：
   - `Cross600 CSD Top-1` **`+8.17pp`**（`34.50% → 42.67%`），`Causal Δ` **`+5.83pp`**；
   - `Artist-OOD` 2-way 跟随 **`+11.66pp`**（`74.17% → 85.83%`），`Δ_ref_dino` 近乎翻倍（`0.1892 → 0.3690`）；
   - `Movement-OOD` 2-way 跟随 **`+8.33pp`**（`84.17% → 92.50%`）；
   - `Instance-Swap` 2-way 跟随 **`+8.33pp`**（`75.00% → 83.33%`），`Δ_ref_dino` 翻倍（`0.1445 → 0.2878`）。
2. **`3060 12GB WDDM` 显存溢出定位与 Gradient Checkpointing 修复**：
   初版 `O3` 在 `step=250` Warmup 结束开启 `swap_micro=2` 时，同时持有 4 张 `512×512` `S10` + `VGG` 计算图导致显存突破 Windows WDDM 可用额（`12,033 / 12,288 MiB`）并退化至 PCIe 共享内存换页。将 `losses.py` 中可微 `S10` 与 `VGG` 切入 `torch.utils.checkpoint(..., use_reentrant=False)` 并改为每步 `4 × M=1` 微步后，`O3` 全程峰值显存锁定 **`5.18 GB`**，`1,400` 步平滑收敛（`flow: 0.4541 → 0.4396`，`swap: 0.1880 → 0.0835`，耗时 `7083.9s`）。
3. **当前结构保持短板与根因**：
   - `tau0=0.50` 下使用低引导（`wj=2.2`）会出现明显源风格锁定（`O0/O1` Top-1 仅 `14.5%–14.8%`）；而降低 `tau0`（`0.00–0.35`）虽解锁强风格与 OOD 跟随，`O3` 因使用随机高斯线性插值起点且无 V34 的 `A3`（低频亮度+色彩正交投影解析起点），`DINO-C` 落在 `0.32–0.44`（同时 `SG-25` 为跨内容极强抽象组合，`DINO-C` 降到 `0.10–0.19`）。
4. **RTX 3060 端到端 `RGB→RGB` 耗时剖析（`O3.pt` 实测）**：
   - 原默认 3 分支 6 步（`wc=1.6, steps=6`）：`273.48–315.87 ms/img`（`3.17–3.66 img/s`）；其中 `SD-VAE encode` 占 `~76 ms`、`特征提取` 占 `~41 ms`、`Flow UNet (18 NFE)` 占 `~107–141 ms`、`S10 decode` 占 `~49 ms`。
   - 切换为 2 分支 CFG + 4 步 DPM-2M（`wc=1.0, steps=4`）：
     - `batch=1`：`237.82 ms/img`（**`4.20 img/s`**，`flow` 降至 `70.95 ms`）；
     - `batch=4`：**`190.79 ms/img`**（**`5.24 img/s`**，达标 `>= 5 img/s`）；
     - `batch=8`：**`182.05 ms/img`**（**`5.49 img/s`**，`feat=9.52 ms`, `flow=33.29 ms`）。

## 6. 未完成队列与后续建议

截至用户要求中止时刻（2026-11-26 20:29），以下原计划实验尚未跑完或未启动：
1. `O3_t50 / O3_t65 / O3_t80`（检验更高 `tau0` 是否能让 `O3` 在 `DINO-C >= 0.60` 水位仍保持高 `CSD Top-1`）；
2. `O3_fast_t35`（`steps=4, wc=1.0` 的 `test750` 与 OOD 质量验证）；
3. `O4`（`base_dim=204`, `~44M` 容量扩容消融）及 `summarize_and_grid.py` 视觉拼图导出。

**若后续重启冲刺 `test750 (DINO-C >= 0.60, Top-1 >= 60%)` 闭环**：建议直接把 **V34 的 `A3` ($L_{\mathrm{low}}+P_C$) 解析起点**引入开放域推理（替代纯 `eps` 线性混合，直接把低频构图与色彩投影注入起点的同时清零源高频画法），再叠加 `O3` 的 `Reference Swap` 配方与 `O4` 44M 扩容。
