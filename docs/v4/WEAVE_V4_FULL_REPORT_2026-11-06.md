来源：`../pseudo_gt_24h/eval_render/*/v4_eval750.json`（字段 `cross600` / `same150` / `all750`）；`runs/12h/anchors/base_ep10_750_512/results_split.json` `[A]`

### 1.2 为什么 750 的 DINO-S 被 150 个同风格任务系统性抬高

A0（base_ep10）三口径的 DINO-S 是 750 = **0.490226**、600 = **0.391857**、150 = **0.883699** `[A]`。
750 恰是 600 与 150 的样本加权平均：

```
(600 × 0.391857 + 150 × 0.883699) / 750 = 0.4902256
```

150 同风格任务的生成图与参考图只差风格内样本差异，DINO-S 天然接近 0.88；混入后把 750 抬高了 **+0.0984**。因此：

- 用 750 判断"风格迁移是否学到新风格"会系统性乐观；
- 用 750 判断"身份是否保持"又会被 600 跨风格的 0.39 系统性拉低；
- 唯一正确的读法是拆开：600 看增益、150 看保持、750 只与历史锚点对齐。

同一事实在数据侧也成立：D_r0 的 750 DINO-S 为 **0.49024**，与锚点 0.49023 对齐；同风格 150 的 `dino_dStyle` 为 **−0.01356**（CI [−0.01710,−0.01002]），说明 D_r0 自己也略伤同风格身份。`[A]`（`runs/p2/p2_cross_style.json` → `historical_750` / `same_style_150`）

### 1.3 0.50523 的来历，以及为什么不能挪用到 600、不能当 CSD 门槛

- 0.50523 = **0.49023 + 0.015**。0.49023 是 A0 的 750 DINO-S（0.4902256）；+0.015 是"S1 相对锚点的数据回收余量"，属于**工程设定** `[C]`，不是论文阈值。
- **不能用于 600**：600 的锚点是 0.391857，0.50523 比它高 **+0.11337**，任何 600 结果都不可能达到，作为门槛没有信息量。600 只能与 600 锚点同口径比较。
- **不能作 CSD 门槛**：0.50523 是 DINO-S（DINOv2-small CLS 余弦、750 聚合）的刻度；CSD ΔT 是"生成图对目标风格原型减源图对目标风格原型"的差值，量纲与尺度完全不同。把 0.50523 套到 CSD ΔT 上属于口径错配。
- 同理，S1 使用的另外三个门控阈值（DINO-C ≥0.86462、CLIP-S ≥0.71463、LPIPS ≤0.27203）都是"锚点 ± 固定 margin"的工程规则（DINO-C −0.015、CLIP-S +0.01、LPIPS +0.01）`[C]`；报告时必须与锚点值一起给出，不能单独当论文阈值。

### 2.3 DINOv2-small（历史可比）

- 该指标用于与 0.49023 历史锚点对齐，不作为风格可分性的唯一依据。

### 2.4 Patch-SWD

- 定义：生成图与目标风格参考集的 patch token 分布之间的 **sliced Wasserstein distance**，`num_projections=64`。
- 报告字段 `swd_gain = swd_base − swd_gen`，**正值 = 更接近目标风格 token 分布**。
- 来源：`runs/p3/p3_p4.json` → `definitions.swd_gain`；实现于 `tools/pseudo_gt/v4_eval750.py` `[A]`

### 2.5 ΔT / ΔS / ΔM 与四分格

定义（全部以 cell A 的 VAE 往返为基线）：

```
ΔT = cos(f(gen), proto_target) − cos(f(src), proto_target)
ΔS = cos(f(gen), proto_source_style) − cos(f(src), proto_source_style)
ΔM = ΔT − ΔS
```

来源：`runs/p3/p3_p4.json` → `definitions.baseline`、`runs/p1/auroc_csd_dm.json` → `delta_m_setup` `[A]`

四分格判读（`ΔT` 行、`ΔS` 列）：

| | ΔS > 0（源风格被保留/增强） | ΔS < 0（源风格被剥离） |
|---|---|---|
| **ΔT > 0** | 风格换过去了但源风格还在：混合/双风格 | **理想格**：目标风格增强、源风格剥离，ΔM 最大 |
| **ΔT < 0** | 两头都丢：退化 | 源风格被剥离但目标没学到：只破坏 |

本报告的主指标取 ΔM（= ΔT − ΔS），因为它同时惩罚"只剥离不增强"和"只增强不剥离"。`[C]`（判读规则为定义，不是测量）

### 10.6 TRT decode batch：engine 不能改 profile，只能重建

- `build_trt_engines.py` 对每个 (size, batch) 编译**固定 shape**：`shape=(batch,4,lat,lat)`，`profile.set_shape("z", shape, shape, shape)`（`tools/trt/build_trt_engines.py#L55-L58`）。**已编译 engine 的 profile batch 不可修改**，只能按新 batch 重建。
- 运行时按 `(size, batch)` 查 engine；缺失则 `fallbacks += 1` 并回落 `decode_latent(vae, z)`（`tools/trt/trt_vae_decoder.py#L31-L35`、`#L56-L66`）。
- 构建结果 `[A]`：

| batch | engine | 大小 | 构建耗时 |
|---|---|---|---|
| 8 | `vae_decoder_512_b8_fp16.engine` | 102.1 MB | 既有 |
| 16 | `vae_decoder_512_b16_fp16.engine` | 98.4 MB | 392.1 s |
| 32 | `vae_decoder_512_b32_fp16.engine` | 100.3 MB | 719.0 s |
| 64 | **构建失败** | — | workspace 6144 MB 不足（报 6.44 GB tactic），`IBuilder::buildSerializedNetwork` 返回 None |

- 因此 decode batch 16/32/64 的**单张 decode 耗时、整链 imgs/s、峰值 VRAM、与 b8 的数值差：全部未观测**（b16/b32 engine 刚建成，b64 无 engine）。`[D]`
- PyTorch fp16 decode 对照：仅试过 `batch=32 + decode=32`，**在 11748 MiB 被 OOM 杀死（rc=143，441 s 未完成）**；这是实测失败，不是估算。`[A]`
- 若要继续：用 `--workspace_mb 12288`（或更高）重建 b64；或在 b16/b32 engine 上直接跑 decode 分档（不需要重建）。

## 11. 红线与教训

1. **单 GPU 任务**。WSL 只有 15 GB 内存，三个进程并行时被压垮并重启；渲染、训练、TRT 构建必须串行。
2. **后台进程必须 `setsid -f`**。普通后台任务在 WSL 会话退出时被杀（bench2 与 TRT build 曾出现空日志、无进程）；后续一律 `setsid -f`。
3. **`effective_coverage` 不能写名义值**。旧 manifest 的 0.25 是名义覆盖率，实测 P5=0.2340、E3=0.2406/0.1817；已改为 `effective_coverage_measured` 并在 commit 229895e 修正。`[A]`
4. **"1/10 可行性"是小样本假象**。单配置 222/300（74%）看起来可用，但放大到 300 张、8 Pattern 合取后只剩 173–189（57.7–63.0%）；不能用单 layout 的通过率推全局。
5. **约束合取 vs 单布局是口径陷阱**。R64/S64/F64 恒 300 不代表"可行池 300"；8 Pattern 同时成立只有 173/189/184（pool3 184）。引用时必须写清是"单 Pattern"还是"合取"。
6. **200 张快筛不是结论**。`v4_eval200` 只能作内部曲线；所有对外数字必须是 750/600/150 全量。
7. **750 聚合抬高 DINO-S**。用 750 判断风格增益会系统性乐观 +0.0984；必须拆分。
8. **b128 不可用**。峰值 10056 MiB 已超 10 GB，且 640/750 张位级不一致；不要为了"吃满显存"牺牲可复现性。
9. **ODE fp16 不是批不变的**。b8↔b≥32 像素差 0.16/255、CSD ΔT 差 1.5e-4；任何换档都必须重跑评测，不能用旧值。
10. **TRT engine 固定 shape**。换 batch 只能重建；缺失时回落 torch，batch 32 即 OOM（11748 MiB）。
11. **口径必须带来源**。同一指标在 256px 与 512px、不同 split、不同 margin 下不可混用（例如 `base_ep10_600` 是 256px，不得与 750/512 表并列）。
