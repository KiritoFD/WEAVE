## 2. 第一轮后训练（PT_A/B/C0/C，均从原 ckpt 独立微调）

| 臂 | 方案 | 结论 |
|---|---|---|
| PT_A_balance | 五画派均衡 FM，1200 upd | 中性：dino_c +.006 / lpips −.006（配对 bootstrap 显著但小），风格轴不动 |

**结论**：均衡/频带加权 FM 只买到内容保持的小幅改善；直接优化风格判别器奖励会被"破坏内容刷分"路径击穿。

RGB-H2（V11b 旧 ckpt + H2_c256 重训 + 强度扫描）：默认强度 no-op；加强后只有通用笔触、
correct/wrong Style-ID 不可区分 → 判负。瓶颈在训练任务而非权重容量。

## 4. Style-Bridge PT（P1–P5，本轮核心）

**动机**：V15 训练只见"目标风格=样本自身风格"的 FM 对，从未直接监督
"已带他画派外观 → 恢复指定目标画派且保留空间内容"。R1 引导已证伪，
本方案用**同一真实画作做端点**的合成桥接：`z_tilde=T_r(z)`（V6 DWT 统计扰动，
强度 {0,.5,1}），`z_tau0=(1-τ0)ε+τ0·z_tilde`，线性路径至 `z_1=z`，
`v*=(z-z_tau0)/(1-τ0)`。无扰动时严格退化为 FM（单测误差 ~1e-6）。

**实现**：`exp/v15/{style_bridge,content_adapter,posttrain_v2,eval_posttrain_v2}.py`、
`exp/v11b/posttrain_h2_bridge.py`。数学单测全过（FM 退化、adapter 零初始化恒等）。

## 5. 跨实验综合判断

1. **风格条件注入是全项目的核心瓶颈**：容量（×4）、训练量（×2）、均衡采样、频带加权、
   R1 判别奖励、H2 编辑——没有任何一项移动 cross600 的目标画派判别指标。
   scaling 只把"像画"推得更高，编辑点 Top1/margin 反而微降。
2. **已证伪路径**：直接优化风格分类器奖励（内容崩塌）、通用纹理增强（不可区分画派）、
   where 自监督、纯容量。
3. **Style-Bridge 改变了结论**：P2 在不增加任何推理参数的情况下，把目标画派
   Top1/margin 推到 dim96 系最高读数（t0=0.4 Top1 .178 ≈ GROUP_A 区间上限；
   t0=0 Top1 .457 vs 基线 .363，仍低于 scaling S6 的 .493）——合成跨风格桥接监督确实触及了条件注入瓶颈，
   但幅度仍小（cross600 Top1 距随机 .20 的门槛刚跨过）。P3 证明"给内容
   捷径"会被 adapter 滥用成恒等映射，内容条件必须加硬约束。
4. **工程结论**：4070 Laptop 上 V15 系训练显存 <100MB（latent 空间小模型），
   评测 ~3.7GB；>2 并发 GPU 进程会 segfault/OOM，需串行。3060 上
   ssh `start /b`/Start-Process 起的进程会随会话被杀，需保持 ssh 前台运行。
