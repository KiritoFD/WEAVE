## 一、P2：动态投影多尺度 SWD ＋ 有界方向排斥（最关键训练阶段）

### 1.1 P2-A：动态投影多尺度 SWD（`exp/v26/train_swd.py`）

- **基座复用**：复用 `exp/v20/submode_patchswd.py` 冻结 VGG-16 提取器，新建 `exp/v26/dynamic_style_swd.py`。
- **特征层选取**：冻结 VGG-16 的 **`relu1_2`、`relu2_2`、`relu3_3`** 三尺度特征图。
- **动态随机投影与同向对齐**：
  - 每个训练 `update` 动态生成 $64$ 个单位范数随机投影方向 $\{u_k\}_{k=1}^{64}$；
  - 同一次距离计算中，**输出 $\hat{x}$、目标参考 $x_{\text{ref}}$、源图 $x_{\text{src}}$ 必须共享完全同一组投影方向与空间抽样索引**；
  - 为压住 3060 12GB 峰值显存，每层空间特征采用固定数量随机 token 抽样（初始建议 $512$ 个 token）；
  - **尺度独立归一化**：各层 SWD 单独按该层参考特征方差/均值做归一化，防止浅层 (`relu1_2`) 大幅值支配深层纹理梯度。

| 训练臂 | 原 VGG 均值风格损失 | 动态多尺度 SWD | 有界排斥 Hinge | 预算与晋级规则 |
|---|---|---|---|---|
| `L0` | 开 | 关 | 关 | 沿用 P1 胜出采样基线对照 |
| `L1` | 开 | 开 | 关 | 先做 100-step 显存/吞吐验证 → 1200 upd + 全量 `test750` |
| `L2` | 关 | 开 | 关 | 先做 100-step 显存/吞吐验证 → 1200 upd + 全量 `test750` |
| `L3` | 保留 `L1/L2` 胜者 | 开 | 开 | **仅当 `L1/L2` 证明 SWD 本身有效后才追加** |

- **长训晋级**：从 `L1` 与 `L2` 中择优（对比 `L0` 在 `ER / Roc / Uki` 纹理与整体 `DINO-C/S/LPIPS/Top-1`）继续延长至 `4000–6000 updates`（可部署至 **4090** 加速跑完并及时拉回）。

### 1.2 P2-B：有界 Source-Style Repulsion（`L3`）

在 SWD 风格距离空间 $D_{\text{style}}$（**严禁用最终裁判 CSD 充当训练损失**）上施加相对有界排斥：
$$L_{\text{dir}} = \mathrm{relu}\Big(m + D_{\text{style}}(\text{out}, \text{ref}) - D_{\text{style}}(\text{out}, \text{src})\Big), \qquad m = \kappa \cdot D_{\text{style}}(\text{src}, \text{ref}), \quad \kappa = 0.1$$
- **自调节物理意义**：当源图与参考图风格原本接近时（同画派/近色调），$m$ 与排斥驱动力自然缩小，避免把同域图像推向畸变。

### 1.3 五重防灰化与结构保护约束

有界 Hinge 不会自动保证内容安全，训练全程必须同时激活：
1. 原结构内容条件（`y16_lcn` + `dino_16` / 经 P1-B 验证通过的表征）；
2. VGG 内容特征保持损失；
3. 亮度结构 LCN 一致性约束（防大面积灰化、对比度抹平）；
4. 局部对比度坍缩惩罚；
5. 梯度范数监控与异常告警（禁止使用像素级 RGB L1 或 GAN 对抗损失）。

### 1.4 P2 验收输出

- 全量 `Cross600` (`DINO-C / DINO-S / LPIPS / Top-1 / Affinity`) + `ER / Roc / Uki` 单独读数；
- 20 条有向路线源锁定率矩阵；
- 同内容更换不同参考图的响应差；
- 高频能量谱与局部对比度分布 vs. 灰白糊片盲目检对比。

## 二、P3：二选一主攻——非对称参考纹理（P3-A）或轨迹监督（P3-B）

> **不强求两条分支都训到底**：由 P0-B 遥测与 P2 消融共同决定 P3-A 与 P3-B 的先后与取舍（如 4090/3060 充裕，可在主线确定后并行验证次优分支的 1500-step 探针）。

### 2.1 P3-A：Asymmetric Source-16 / Reference-MultiScale（`exp/v26/ref_multiscale.py`）

- **触发条件**：P0-B 显示 `RefAttnV24` 局部 `Value` 对输出影响弱、跨画派匹配退化，或 P2 强化 SWD 后 `Rococo / ER` 仍缺少局部笔触。
- **结构约束（防重新引入源锁定）**：
  - **源内容 Query 严禁升分辨率**，严格维持 `16×16`；
  - 参考侧拆分为：用于语义对应的 `K_ref16`、现有 `V_ref16`（ConvNeXt），以及新增参考局部高频纹理统计 **`T_ref32`**（可选 `T_ref64`）；
  - 复用 `16×16` 空间注意力匹配矩阵 $A$ 将匹配后的参考高频统计调制注入解码侧 `32×32` 特征层，**不新建第二套高分辨率全局 Attention**。

| 实验臂 | 参考特征配置 | 新增参数上限 | 训练预算 | 决策规则 |
|---|---|---:|---:|---|
| `M0` | 原 `V16` | 0 | 对照 | 基线 |
| `M1` | `V16 + T_ref32` 纹理统计 | `≤ 0.5M` | 1500 updates | 若无改善，**直接取消 `M2`** |
| `M2` | `M1 + T_ref64` 高频统计 | 轻量增量 | 1500 updates | 仅 `M1` 明确正向后追加 |

### 2.2 P3-B：Stochastic-Step Truncated Rollout（`exp/v26/train_rollout.py`）

- **触发条件**：P0-D 发现单步 Euler 清洁端预览与实际多步 RK2 终态偏差较大，需要改善训练—推理轨迹一致性。
- **第一轮显存与吞吐摸底（先在 3060 验证安全水位，不可预设能跑 `batch=8`）**：
  依次测试：2 步 Euler 全可微 → 4 步 Euler + Activation Checkpointing → 2 步 RK2 全可微 → 随机截断多步 + 单步可微；任一配置在 3060 超 `10.5 GB` 或梯度爆炸即自动降级至更轻方案。
- **第二轮随机步截断训练**：
  - 每次随机抽取 $k \in \{2, 3, 4\}$，前 $k-1$ 步在 `torch.no_grad()` 下积分推进至 $z_k$；
  - 仅第 $k$ 步打开梯度，计算清洁端线性外推代理：$\hat{z}_{\text{clean}} = z_k + (1 - t_k) v_\theta(z_k, t_k)$，对其施加动态 SWD 与内容保护损失；
  - **必须同步评测完整 10 步 RK2 终态结果**，防止清洁端外推代理失真（仅当显存与吞吐允许时，再追加 4 步完整可微 Rollout 对照）。

## 三、P4：无训练减法与条件 Reflow 少步压缩（`exp/v26/few_step.py`）

> **准入门槛**：仅当 P2/P3 产出了满足风格与内容提升的候选模型后，才启动 P4-B 少步蒸馏；若 4–6 步本身未崩溃才值得投入 Reflow。

### 3.1 P4-A：无训练减法与模块剪除消融

- 直接复用 P0-D 调度发现（不重复扫已判负组合），聚焦对比 `10-step RK2`、`6-step RK2`、`4-step RK2`、`4-step Euler`；
- 在当前最佳权重上逐一做**可删性消融**（基于贡献度而非参数量直观猜测）：
  1. 无效的条件分支或冗余全局参考编码；
  2. 门控接近常零的 `RefAttn` Gate；
  3. 重复的特征提取调用；
  4. 对当前模型无净增益的多余潜锚点。

### 3.2 P4-B：条件 Reflow 短路径微调

- **严格同配教师生成**：冻结当前最佳 10 步教师，在训练集内部 `(源内容, 目标参考)` 对上生成确定性配对轨迹 `(z_start, condition, z_teacher_final)`；学生与教师必须共享完全相同的参考条件、内容编码、锚点定义、固定 SR-CFG 强度与训练样本域；
- **短路径目标**：优先测试 **`4-step Euler`** 与 **`2-step Euler`**，先跑 `1500–2500 updates` 监测是否发生内容坍缩或纹理退化；
- **方法论隔离**：本阶段**仅使用简单条件 Reflow**，严禁同时堆砌 MeanFlow 与 Shortcut 两套目标函数。若简单 Reflow 掉点不可接受，将其判负并保留最优 4–6 步 RK2，把 MeanFlow/Shortcut 留待独立立项。

### 3.3 P4 正式速度验收（RTX 3060 实测）

必须分项实测并报告：
1. 首次参考编码 ＋ 单张生成（`b=1`）；
2. 参考已缓存 ＋ 单张生成（`b=1`）；
3. 最大安全 batch 吞吐量（`img/s`）与峰值显存（`<10.5 GB`）；
4. 主干 Flow 网络耗时 vs. 冻结前端（A0 Encode + DINOv2 + ConvNeXt + S10 Decode）耗时拆分；
- **反虚标规则**：若冻结前端本身已耗费较多时间，**严禁仅凭 Flow NFE 减少就宣称端到端达标 `250 ms`**；挑战 `250 ms` 必须依据真实 `RGB→RGB` 端到端测量与前端共享/流水优化后的实测结果。
