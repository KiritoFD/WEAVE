# 通用大模型为何在风格迁移上综合表现弱且推理极慢

> 核心结论：以 **`Seedream 4.5`** 为代表的通用图像生成/编辑大模型，表面上看 `DINO-C` 较高（`0.7343`）、`LPIPS` 也不难看（`0.5202`），但一旦放到**内容—风格双维平衡**与**端到端推理延迟**下统一评测，就会暴露出**“改图保守（风格几乎没迁过去）、综合均衡分偏低、且单图耗时比专用单步模型慢两个数量级”**的结构性短板。

相关数据与口径见 [指标台账](metrics.csv)、[Pareto 画图口径](pareto.md) 与 [pareto.py](../../src/eval/pareto.py)，对应图谱见 [速度-负对数综合得分图](figures/speed_composite_score.svg)、[速度-负幂均值图](figures/speed_power_mean.svg) 与 [内部前沿对照图](figures/ours_pareto.svg)。

## 二、为什么通用大模型显得“综合表现不好、而且很慢”

### 1. 高 `DINO-C` 掩盖了“几乎没做风格迁移”的保守行为

- 对比无编辑恒等端点（`ema_s4000 λ=0.0`：`DINO-C = 0.9590`, `DINO-S = 0.3735`），`Seedream 4.5` 的 `DINO-S = 0.3885` 仅仅只比原图本身的风格基准高 **`+0.0150`**。
- 也就是说，通用编辑大模型在收到“保留原图内容 + 应用目标风格”的冲突指令时，倾向于做轻微色调/局部纹理微调来压低结构改写风险，保住了 `DINO-C = 0.7343` 和 `LPIPS = 0.5202`，却没有把真实画作的笔触尺度、构图节奏与笔法肌理迁过去（`DINO-S` 显著落后于 `AesPA 0.4661`、`PRISM-1 0.4431`、`PRISM-Flow D6 0.5107` 与 `StyleGallery 0.5604`）。

### 2. 一旦改用“惩罚短板”的自然综合指标，弱项立刻显形

- 在简单的线性加权或只看内容相似度的视角下，高 `DINO-C` 很容易帮保守模型“遮短”。
- 而当改用不引入硬门槛、纯平滑或无参数的均衡综合分时：
  - 在负对数平滑最小值 $S_{\mathrm{LSE}}$ 上，`Seedream 4.5` 仅为 **`5.629`** —— 不仅落后于 `StyTr2 (5.773)`、`AesPA (5.739)`、`StyleGallery (6.017)`，甚至略低于比它更快的 `SaMAM (5.668)`，与 `PRISM-1 (6.273)`、`PRISM-1-Unified λ=0.45 (6.311)`、`PRISM-Flow D6 (6.367)` 相差超过 **`0.64–0.74`**。
  - 在零参数负幂均值 $M_{-4}$ 上，`Seedream 4.5` 仅为 **`0.4534`** —— 虽然因 `StyleShot (0.4100)` 与 `StyleID (0.4306)` 严重破坏内容而被排在其上，但仍显著低于均衡工作点 `AesPA (0.5146)`、`PRISM-1 (0.5116)`、`PRISM-Pro T4 (0.5231)`、`PRISM-Flow D6 (0.5645)` 与 `StyleGallery (0.5831)`。

### 3. 速度慢了 2 个数量级，算力没有转化成有效迁移增益

- `Seedream 4.5` 单图耗时 **`2000.0 ms`（`0.50 img/s`）**；而专用单步架构 **`PRISM-1` 仅需 `17.04 ms/img`（`58.69 img/s`）**：
  - 推理速度领先 **`117×`**；
  - 同时在 `DINO-C`（`0.7440 > 0.7343`）、`DINO-S`（`0.4431 > 0.3885`）、`CSD Top-1`（`44.33% > 37.30%`）、`CLIP-S`（`0.6880 > 0.6744`）、`Style Affinity`（`0.5655 > 0.5314`）和 `LPIPS`（`0.5057 < 0.5202`）上实现**全指标同时反超**。
- 其本质原因在于：通用大模型把绝大多数参数与多步采样预算消耗在**开放域视觉—语言语义对齐、长上下文自注意力重绘与泛化先验维持**上，缺少针对风格迁移的显式商—纤维解耦结构（$\Pi_\perp / \Pi_\parallel$）与高频局部分布传输（如 Patch-SWD + 像素感知桥），导致单步无法直达、多步又受制于指令编辑保守惯性。

## 三、后续横向验证计划（开源多图编辑大模型补齐）

为了检验上述结论是否在开源通用多图编辑大模型上同样成立，已对本地 `4090` 算力节点的模型资产完成核查：

1. **`MOSS-Image` 不适合作为参考图风格迁移参照**：4090 上既有 `Comfy-Org/MOSS-Image` SFT BF16 权重为纯文生图 dense 管线（`pipeline_moss_image.py` 明确不提供 reference-image 编辑接口），本身不具备图像条件编辑能力，不强行纳入对比。
2. **优先补齐 `Qwen-Image-2.1-Turbo` 与 `Qwen-Image-2.1`（Base）**：两者具备原生多图参考 + 文本指令编辑能力（`QwenImage21Pipeline`），后续在 [V28 实验](../v28/PROGRESS.md) 释放 GPU 后，可在同套 `q2a_oracle_cross600` 协议与 `17 ms`–`2000 ms` 速度横轴下实测其 `DINO-C / DINO-S / CSD Top-1 / ms_per_img` 表现。
